# Интерактивная доска — `app.педобраз.рф/board/`

Холст урока в браузере: рисование от руки, фигуры, стрелки с привязкой, текст,
картинки, личная библиотека фигур, экспорт в PNG/SVG и в файл `.excalidraw`.
Учителю не нужно ничего устанавливать — только открыть ссылку.

**Бэкенда нет.** Рисунок хранится в IndexedDB браузера учителя и никуда не
отправляется; выгрузка картинкой и в файл считается на клиенте. Нагрузка на наш
сервер — раздача статики, как у `flexbox`, `phet` и `mindmap`.

---

## Что это собрано из

Апстрим — пакет **`@excalidraw/excalidraw` 0.18.1** (MIT), а **не** приложение
excalidraw.com. Разница принципиальная и выбрана осознанно:

| | приложение excalidraw.com | пакет (наш путь) |
| --- | --- | --- |
| Firebase, Sentry, аналитика | зашиты | нет по построению |
| реклама Excalidraw+, их сервер совместной работы | зашиты | нет |
| хранение рисунка | своё | пишем сами (10 строк на IndexedDB) |
| состав меню, экран приветствия | их | наши |

Форк приложения пришлось бы чистить патчами по минифицированному коду — ровно
так в соседнем `mindmap/` файл `patches/apply.sh` дорос до 37 КБ. Обёртка вокруг
пакета ([app/src/main.jsx](app/src/main.jsx), ~260 строк с комментариями) не
содержит ничего лишнего изначально.

## Русский язык: словарь апстрима плюс 56 строк наших

Основной перевод — штатный словарь пакета (`langCode="ru-RU"`), 371 строка.
Но в нём **не хватает 56 строк из 424**, и на их месте редактор молча показывает
английский: ни ошибки, ни пустого места. Так на снимке для лендинга оказалась
подсказка «Нажмите Enter для добавления текста. Hold Ctrl and Arrow key to create
a flowchart» — первая половина переведена, вторая нет.

Что было не переведено: все виды стрелок, «Очистить холст», «Вписать всё в
экран», «Показать сетку», палитра команд, поиск по холсту, названия фигур
целиком, подсказки про обрезку картинки и блок-схемы, часть свойств в панели.

Перевод лежит в [patches/ru-extra.json](patches/ru-extra.json), а
[patches/translate-ru.mjs](patches/translate-ru.mjs) сливает его в словарь
апстрима **до** сборки бандла. Скрипт правит собранный чанк словаря, поэтому
он обязан падать при смене формы чанка — и падает: проверяются и файл, и
`export{…}`, и наличие текста после вставки. Плюс проверка в
[Dockerfile](Dockerfile) — доперевод должен быть виден в готовом бандле.

⚠️ При обновлении апстрима список недостающих строк надо пересчитать: часть
может появиться в их словаре, и тогда наш перевод перекроет их — это не ошибка,
но лишнее. Пересчёт — разбором двух словарей (`dist/prod/locales/ru-RU-*.js` и
`dist/prod/chunk-*.js`, где лежит английский по умолчанию).

## ⚠️ Главная грабля: шрифты уходят на чужой CDN, и молча

Шрифты рисунка (Excalifont, Nunito, Cascadia, Xiaolai — восемь наборов) пакет
грузит **не тегом, а через `fetch`**, а базовый адрес берёт из
`window.EXCALIDRAW_ASSET_PATH`. Если его не задать, работает запасной адрес,
зашитый в код: `https://esm.sh/@excalidraw/excalidraw@0.18.1/dist/prod/`.

Хуже того: **запасной адрес добавляется в список ВСЕГДА**, даже когда свой путь
задан и файлы на месте, — и браузер шлёт запросы по обоим адресам сразу, а не по
очереди. Замерено 23.08.2026 на одном текстовом блоке: 2 запроса к себе и
**230 к esm.sh**.

Поэтому рубежей четыре, и каждый нужен:

1. **Свой путь** — `window.EXCALIDRAW_ASSET_PATH` в [app/index.html](app/index.html).
   Задан абсолютным адресом от `document.baseURI`, а не строкой `"./"`:
   `normalizeBaseUrl` внутри пакета достраивает относительный путь к
   `location.origin`, теряя префикс `/board/`, — шрифты посыпались бы в 404.
2. **Файлы на месте** — [Dockerfile](Dockerfile) кладёт их рядом с `index.html`
   и проверяет `grep`-ом, что и файлы, и путь в разметке существуют.
3. **Вырезанный запасной адрес** — [patches/strip-cdn-fallback.mjs](patches/strip-cdn-fallback.mjs)
   удаляет его из собранного бандла. Правка по минифицированному коду, поэтому
   она **падает**, если апстрим переписал это место: замена ищется ровно одна.
4. **CSP** — `connect-src 'self'` в [nginx.conf](nginx.conf). Единственный
   рубеж, который не зависит от нашей внимательности; до вырезания патчем он
   ловил все 230 запросов (`blockedReason=csp`, наружу не ушло ничего).

## Куда доска ходит наружу

Никуда сама. Замерено после сборки: 14 запросов к своему хосту (0,61 МБ), ноль
внешних.

Три оговорки, чтобы страница «о доске» потом не врала:

- **Виджет «Обращения»** тянет свой JS и CSS с главного домена — это впрыск
  nginx (`educational_stack/nginx/feedback.conf`), общий для всех тренажёров, к
  доске отношения не имеет.
- **Кнопка «Просмотреть библиотеки»** в панели библиотеки открывает каталог
  готовых наборов фигур апстрима на `libraries.excalidraw.com`. Только по клику;
  адрес разрешён в `connect-src`, иначе набор было бы невозможно установить.
- **Окно «Помощь»** (клавиша `?`) содержит ссылки апстрима на их документацию и
  блог. Это ссылки, а не запросы: без клика ничего не грузится.

Встраивание чужих страниц (YouTube, Figma, Giphy) выключено параметром
`validateEmbeddable={false}`, «умные» функции апстрима — `aiEnabled={false}`:
они ходят на их сервер.

## Учительская панель: лист, фон, геометрия

Кнопка «Учителю» в верхней полосе открывает панель
([app/src/teacher/](app/src/teacher/)). Всё в ней сделано публичным API
компонента (`updateScene` / `getSceneElements` / `getAppState`), поэтому
переживёт обновление апстрима.

**Лист — конструктор со слоями** ([app/src/teacher/ruling.js](app/src/teacher/ruling.js),
[RulingDialog.jsx](app/src/teacher/RulingDialog.jsx)), устроенный как инструмент
сетки в ActivInspire, и не из подражания: школьные разлиновки не сводятся к
«шагу клетки». Двойная линовка — это две системы горизонталей с разным сдвигом;
косая линейка первого класса — строки через 9 мм, пунктир ровно посередине и
наклонные под 65°; миллиметровка — три системы разной толщины. Одним набором
параметров это не описать, набором слоёв описывается ровно.

Слой: тип (горизонтали / вертикали / наклонные), шаг и сдвиг в миллиметрах,
угол для наклонных, цвет, толщина, начертание (сплошная/пунктир/точки),
видимость. Слои переставляются, выключаются и удаляются; рядом живой
предпросмотр, размер листа (A4/A3, книжная и альбомная), поле слева и оси
координат. Восемь готовых разлиновок — отправные точки, а не список
возможного: любую можно доправить по слоям.

Считаем **в миллиметрах** (`MM = 4 px`), потому что учитель мыслит именно ими,
а перевод в пиксели делается один раз на выходе. Предпросмотр и настоящий лист
считает **одна и та же функция** `rulingLines` — иначе предпросмотр рано или
поздно начал бы врать, а он ровно для того и нужен, чтобы не врал.

Лист — это НЕ подложка под холстом, а настоящие элементы сцены: подложка не
попала бы ни в PNG, ни в сохранённый файл, а учителю клетка нужна именно на
картинке, которую он отдаёт классу. Лист заперт (`locked`) и собран в группу с
префиксом `pb-sheet-`, чтобы не выделялся вместе с чертежом; «Убрать лист»
ищет по этому префиксу. Настройки разлиновки хранятся в `localStorage`: их
задают один раз и ставят тем же составом весь год.

⚠️ Число линий ограничено (`MAX_LINES = 1500`) и показывается в конструкторе.
Это не осторожность: лист — заблокированные элементы сцены, и десять тысяч
отрезков превращают панорамирование в кисель на школьном ноутбуке.
Миллиметровка на A4 даёт ~660 линий и вставляется меньше чем за секунду.

**Фон** — шесть заливок холста, включая зелёную и чёрную доску. Тёмный фон
заодно переключает перо на белое: это первое, обо что спотыкаются, выбрав
«школьную доску».

**Сетка на экране** — штатный режим Excalidraw (`gridModeEnabled`), бесконечная
и в выгрузку не попадающая, с выбором шага 5 мм / 1 см / 2 см. Она и наш лист
совпадают клетка-в-клетку: масштаб общий, `CELL = 20 px`, `1 см = 40 px`.

**Инструменты ВЕДУТ карандаш** ([app/src/teacher/SnapLayer.jsx](app/src/teacher/SnapLayer.jsx)) —
линейка 20 см, транспортир со шкалой, циркуль и два угольника. Смысл линейки не в том,
чтобы лежать на листе: к ней приставляют карандаш и проводят прямую. Поэтому
карандаш **прилипает к рабочей кромке**: ведёшь рядом — линия идёт строго по
ней, как ни дрожала бы рука. У транспортира ведение по шкале чертит дугу, а
тычок ставит отметку градуса (так и отмечают угол, чтобы потом убрать
транспортир и провести луч). **Циркуль берут за грифель**: игла стоит на месте,
плечо ведёт дугу, а сам инструмент вращается вокруг иглы, как настоящий;
раствор задаётся числом в панели. Инструмент двигают и поворачивают стрелкой —
линия послушно идёт под тем же углом.

Инструменты сверены с эталоном построчно (2026-08-24): перо ставится в любом
месте линейки и угольника, а не только у кромки; линия ложится снаружи кромки
на полтолщины штриха; у линейки миллиметровая шкала по обеим кромкам; на тёмном
холсте инструменты светлеют. Поведение циркуля и остальных сверено с OpenBoard — см.
[docs/board_teacher_tools_roadmap.md](../../docs/board_teacher_tools_roadmap.md),
там же где лежит справочная полка с исходниками эталона.

Как это сделано, не залезая внутрь редактора: Excalidraw не даёт перехватить
рисование, но событие указателя можно забрать РАНЬШЕ него — слушателем на
обёртке в фазе перехвата. Если выбран карандаш и указатель у кромки, событие
забирается себе (`stopPropagation`), линия ведётся по кромке и на отпускании
кладётся в сцену. Иначе не делается ничего, и холст рисует как обычно —
поэтому стрелкой инструмент по-прежнему двигается, а вдали от него карандаш
рисует от руки.

Геометрия кромок лежит в `customData` тела инструмента — **долями от рамки**,
чтобы пережить растяжение; слой прилипания поворачивает её вместе с элементом.

⚠️ **Двойной щелчок по инструменту гасится тем же слоем.** Штатно двойной
щелчок входит внутрь группы и выделяет ОДНУ деталь — и следующее перетаскивание
уносит, например, только жёлтое тело линейки, оставив её шкалу лежать на месте.
Для чертёжного инструмента это поломка: он обязан быть цельным. Заодно гасится
и вторая штатная реакция на двойной щелчок — вписать текст внутрь фигуры.
Если инструмент всё же разъехался (или просто надоел), в панели есть «Убрать
инструменты»: она снимает все группы `pb-tool-*`, а начерченное оставляет.

**Точные фигуры** — отрезок заданной длины под заданным углом, окружность по
радиусу, правильный многоугольник, угол в градусах. Строятся по числам и
текущим цветом пера.

**Все размеры вводятся числом.** Выделили инструмент — в панели появились его
размеры: длина линейки, радиус транспортира, катет угольника, раствор циркуля и
угол поворота (плюс кнопки 0/30/45/60/90°). На интерактивной панели пальцем
точное значение не выставить, поэтому число — основной способ, а рукоятки
остаются для «на глаз». Свой шаг экранной сетки тоже задаётся числом.

⚠️ Правка размера — это **пересборка** инструмента на прежнем месте и под
прежним углом, а не растягивание: у растянутой линейки деления перестали бы
быть сантиметрами, а у транспортира — градусами. У циркуля сохраняется
положение ИГЛЫ: её ставят в точку чертежа. Пересобранный инструмент остаётся
выделенным, иначе после первой же правки поля исчезали бы вместе с панелью.

⚠️ **Любая прямая правка элементов обязана поднимать `version`.**
Автосохранение сравнивает сумму версий (`getSceneVersion`): подвинули элемент,
не подняв версию — сумма прежняя, запись не состоялась, и после перезагрузки
инструмент прыгнул обратно. На экране при этом всё правильно; поймать можно
только сравнив сохранённую сцену с картинкой. Поэтому `rotateGroup` и
`translateGroup` помечают каждый тронутый элемент.

**Измерения** — строка внизу экрана показывает для выделенного длину, угол к
горизонтали, периметр, площадь, радиус, а для двух прямых — угол между ними.
Это и есть транспортир в честном виде: цифра, по которой сразу видно, сошёлся
ответ или нет.

### Грабли, которые видно только по числам (и одна — только глазами)

1. **Конвертер апстрима не считает рамку ломаной по точкам.**
   `convertToExcalidrawElements` оставляет `width`/`height` умолчанием (100×0).
   Нарисуется такая ломаная правильно (рисование идёт по точкам), но выделение,
   поворот и попадание указателя считаются ПО РАМКЕ — транспортир брался бы за
   воздух, а дуга угла обрезалась. Рамку считаем сами в `poly()`, там же
   приводим точки к каноническому виду (первая — в начале координат).
2. **Заливка ломаной появляется только у замкнутого контура, и замыкать надо в
   ПЕРВУЮ точку.** Повтор последней точки контур не замыкает: транспортир
   оставался прозрачным, и никакой ошибки при этом нет.
3. **У ломаной `x/y` — это её ПЕРВАЯ ТОЧКА, а не угол рамки.** Рамка растёт от
   неё в ту сторону, куда идут точки: у транспортира они уходят влево и вверх,
   поэтому рамка лежит на полшага левее и выше `x,y`. Наивная формула
   `x + width/2` уводила шкалу на её собственную ширину в сторону — прилипание
   «работало» в пустоте рядом с инструментом. Самое неприятное: **проверка
   ошибалась ровно так же и была зелёной**; поймал только снимок экрана. Отсюда
   правило для этого места: любую геометрию инструментов сверять глазами по
   снимку, а не только числами.

## Сохранение и выгрузка: что проверено

Прогон 2026-08-24 по контейнеру: собрана доска (лист в клетку, линейка,
транспортир, начерченная по линейке линия), сохранена «Сохранить как…» в файл,
открыта обратно перетаскиванием и выгружена в SVG и PNG.

- **В файле** 158 элементов: оба инструмента с их `customData` (`pbTool`,
  `params`, `edges`, `arc`), лист из 104 частей — весь заперт, группы целы,
  начерченная линия на месте.
- **После открытия файла** возвращаются все 158 элементов, настройки
  инструментов целы, и **прилипание работает на загруженной линейке** — то есть
  инструмент остаётся инструментом, а не картинкой.
- **В SVG** есть тело линейки, подписи её шкалы и 103 линии клетки листа.
- **PNG** — 157 КБ, не пустой.

⚠️ Пункт «Сохранить как…» пришлось добавить отдельно
(`MainMenu.DefaultItems.Export`): `SaveToActiveFile` показывается ТОЛЬКО когда
файл уже открыт, поэтому сохранить доску в файл было нечем, хотя обещание
«открыть завтра и продолжить» уже стояло и в описании, и на лендинге.

## Хранение рисунка

IndexedDB, а не `localStorage` (в отличие от `mindmap`): на доску вставляют
фотографии, Excalidraw держит их в сцене строками `data:`, и потолок
`localStorage` (~5 МБ) кончился бы на первой же паре снимков с телефона — молча,
посреди урока.

Три хранилища: `scene` (фигуры + настройки пера), `files` (картинки),
`library` (личная библиотека фигур). Запись с дребезгом 800 мс и немедленно при
скрытии вкладки; картинки переписываются, только когда изменился их состав.

Из `appState` сохраняется **закрытый список** полей (положение и масштаб холста,
фон, тема, сетка, настройки пера) — временная жизнь интерфейса (какое окно
открыто, что выделено) между заходами не нужна и местами вредна.

⚠️ Чтение при старте ограничено **пятью секундами**: Excalidraw держит заставку
«Загрузка сцены…» ровно до того, как разрешится промис `initialData`, а
IndexedDB умеет не отвечать вовсе (база, занятая соседней вкладкой, уходит в
`onblocked`, и ни `onsuccess`, ни `onerror` уже не придут). Без ограничения
доска в такой вкладке не открылась бы никогда.

### Заготовки учителя в Паспорте (Пульт, п. 2.6)

Единственный путь, по которому рисунок уходит с компьютера, — явное нажатие
учителя. `nginx/passport.conf` подключает `/pb-passport.js`; вошедшему учителю он
рисует в левом нижнем углу кнопку «☁ Заготовки», которая открывает вкладку Пульта
(`pb-teacher.js`, `tabBoards`). Сцену Пульт берёт и подставляет через
`window.pbBoard` (`get` / `set`), который `main.jsx` объявляет, когда холст готов.
Сервер — `POST/GET /api/passport/boards` (до 50 заготовок, до 2 МБ каждая — с
запасом под фото). Ссылка «Открыть» с другой страницы ведёт на
`/board/?pb_board=<id>`. Ученикам и гостям ничего не меняется.

## Сборка и выкат

```bash
docker compose up -d --build board      # из корня репозитория
docker compose exec -T caddy caddy reload --config /etc/caddy/Caddyfile
```

⚠️ **Сборке нужна сеть хоста** (`build.network: host`, уже прописано в compose):
как у `mindmap`, `circuitjs`, `velxio` и `phet`, из bridge-сети docker'а
`registry.npmjs.org` уходит в таймаут, а с хоста отвечает.

Версия апстрима прибита точно (`"@excalidraw/excalidraw": "0.18.1"`, без `^`) и
`npm ci` берёт зависимости из `package-lock.json`: `^0.18.1` однажды приехало бы
новым мажором посреди учебного года.

Локальная проверка без docker:

```bash
cd educational_stack/board/app
npm ci
node ../patches/translate-ru.mjs        # доперевод — ДО сборки
npm run build
node ../patches/strip-cdn-fallback.mjs  # вырезать запасной CDN — ПОСЛЕ
cp -r node_modules/@excalidraw/excalidraw/dist/prod/fonts dist/fonts   # иначе шрифты уйдут на CDN
```

## Что проверено (2026-08-23)

Сквозной прогон в браузере без интерфейса по контейнеру с боевыми впрысками:

1. доска открывается, интерфейс русский;
2. нарисованное попадает в IndexedDB (2 фигуры, `appState` без временных полей);
3. после перезагрузки страницы рисунок на месте;
4. шрифты рисунка грузятся со своего хоста (2 файла, 39 КБ), CSP их не режет;
5. запросов мимо своего хоста — ноль;
6. интерфейс русский целиком, включая доперевод (проверено снимком: подсказка
   про блок-схему больше не наполовину английская).

## Что дальше (не сделано намеренно)

Полный разбор — [docs/board_teacher_tools_roadmap.md](../../docs/board_teacher_tools_roadmap.md):
чем набор инструментов у OpenBoard и ActivInspire отличается от нашего, что
брать следующим и как оно должно себя вести. Коротко: из чертёжных не хватает
только циркуля, дальше идут накладки для ведения урока (шторка, прожектор,
таймер, кубик).


- **Остатки набора ActivInspire** — шторка, прожектор, таймер, кубик, генератор
  имён. Линейка, транспортир, угольники, лист в клетку и измерения уже есть
  (см. выше); эти пятеро — не про чертёж, а про ведение урока, и делаются
  отдельным слоем поверх холста, а не элементами сцены.
- **Совместный режим.** Требует ретранслятора (`excalidraw-room` — stateless,
  сессии E2E-шифрованы). Включение будет отдельным, видимым решением: сейчас у
  доски бэкенда нет вовсе, и это её главное свойство.
- **Лендинг на главном домене** — как `/mindmap/` и `/labs/`.
